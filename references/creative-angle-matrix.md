# Creative Angle Matrix

Use this matrix to design and compare genuinely different buying arguments before drafting. A matrix is a planning tool, not a quota generator. Never force an angle count, funnel split, or theoretical framework that the user did not request.

## One row per buying argument

Record the following for each proposed angle:

| Field | What to decide |
|---|---|
| `angle_id` | Stable identifier for the argument. |
| `funnel_stage` | The audience's current decision state and the task this message must complete. |
| `target_hypothesis` | Who may care and in what real situation; keep inference labeled as a hypothesis. |
| `shopper_motivation` | What the person wants to achieve, avoid, choose, or feel. |
| `shopper_tension` | The concrete friction, doubt, trade-off, or unmet desire in that situation. |
| `desired_progress` | What useful next state or decision the shopper wants. |
| `buying_argument` | Why this product, offer, or next step is relevant to that motivation. |
| `evidence_and_limits` | Sources supporting product facts and which shopper assumptions remain hypotheses. |
| `opening_route` | A scene, question, choice, contrast, useful result, or curiosity that makes this angle recognizable. |
| `proof_route` | The relevant fact, demonstration, comparison, or selection cue. Do not invent proof. |
| `cta_job` | The next action and what decision information the destination provides. |
| `nearest_angle_and_difference` | The closest angle and the buyer motivation/progress/reason that differs. |

## Distinctness test

Two angles count as distinct only when they give a shopper a meaningfully different reason to consider or choose the offer. Compare motivation, tension, desired progress, buying argument, evidence role, and funnel task. A different hook, adjective, format, framework, CTA, visual, or persona label alone does not count. If the buyer's reason remains the same, merge the rows or replace one argument.

Do not infer that different features automatically mean different benefits. Likewise, one feature may support more than one angle only if the shopper motivation and decision it serves are genuinely different and each bridge remains evidence-bounded.

## Use frameworks as tools

JTBD, awareness stages, value frameworks, Six Thinking Hats, MECLABS, and persuasion sequences may help diagnose an angle. Select only frameworks that answer a real decision question. Their labels do not prove audience demand, create evidence, or make arguments distinct. MECLABS is a diagnostic heuristic, not a conversion score.

## Counts and confirmation

Honor explicit requested counts and stage distributions. If count or funnel scope is missing and materially changes the work, ask one concise clarification; otherwise state a practical assumption and proceed. Do not generate 24 combinations as a default. Recommend a focused set from the available evidence, then seek approval only when the task requires approval or the next step is consequential. If the user already gave the count, deliverable, and permission to draft, do not add a second conversational confirmation; record that explicit instruction in the existing approval artifact required by the runtime.

Before copy drafting, present the matrix in a compact comparison table when the user requests strategy, multiple non-overlapping angles, or a reviewable proposal. Otherwise use it internally and deliver the requested copy format.

## Funnel decision task

| Stage | Reader needs | Copy should help them do |
|---|---|---|
| TOFU | Recognize a relevant desire, scene, or friction. | Decide whether to pay attention or explore. |
| MOFU | Compare options or resolve a specific hesitation. | Decide what to inspect and why. |
| BOFU | Resolve the remaining purchase barrier. | Complete the next purchase action using verified terms only. |
